# Методика бенчмарка

Опциональный бенчмарк измеряет полный цикл процесса через публичный API `ProcessRunner`.
Каждая итерация создаёт исполняемый файл бенчмарка как дочерний процесс, выполняет
минимальный дочерний путь, ожидает нулевой код завершения, закрывает нативные ресурсы и
проверяет результат внутри измеряемого полного цикла. Контролируемое выполнение и явно
заданная политика только запуска выводятся отдельно.

## Сборка и запуск

```bash
cmake -S . -B build-bench -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=OFF -DMWF_BUILD_EXAMPLES=OFF -DMWF_BUILD_BENCHMARKS=ON
cmake --build build-bench --config Release --parallel 2
./build-bench/MicroWorkflowFrameworkBenchmark 100
```

При использовании многоконфигурационного генератора Windows запускайте
`build-bench/Release/MicroWorkflowFrameworkBenchmark.exe`.

## A/B-сравнение Linux между v0.1.0 и v0.1.1

Дата: 2026-08-25.

| Поле | Значение |
| --- | --- |
| Процессор | AMD Ryzen 7 PRO 1700X, 8 ядер / 16 логических процессоров |
| Память | 31.95 GiB |
| Среда | Контейнер Ubuntu 24.04 в Windows 10 Pro |
| Компилятор | GCC 13.3, Release |
| Нагрузка | 7 раундов × 200 последовательных запусков на сценарий |

| Сценарий | Медиана запусков/с | Изменение относительно v0.1.0 |
| --- | ---: | ---: |
| Базовый контролируемый запуск v0.1.0 | 181.34 | Базовая линия |
| Быстрое ожидание контролируемого запуска v0.1.1 | 205.35 | +13.2% |
| Только запуск v0.1.1 через `posix_spawnp` | 215.85 | +19.0% |

Старая ревизия и v0.1.1 были скомпилированы в одном контейнере и запускали собственные
исполняемые файлы бенчмарка. Контролируемый режим сохраняет гарантии группы процессов и
Linux parent-death. Режим только запуска намеренно отключает владение потомками и
использует более дешёвый платформенный путь.

## Внешнее сравнение в Windows

Внешний бенчмарк использует Boost.Process 2.0 из Boost 1.90 и libuv 1.52.1. Все четыре
сценария запускают один исполняемый файл с одним аргументом и ожидают проверенный нулевой
код завершения. Семь чередующихся раундов по 50 запусков дали следующие медианы:

| Сценарий | Медиана запусков/с |
| --- | ---: |
| libuv | 31.92 |
| Контролируемый MWF | 31.57 |
| MWF только для запуска | 27.78 |
| Boost.Process 2.0 | 24.67 |

Машина: AMD Ryzen 7 PRO 1700X, Windows 10 Pro, MSVC 19.51 Release. Разброс между раундами
был большим, потому что запуск исполняемого файла, проверка endpoint и активность
планировщика преобладают над накладными расходами фреймворка. Эти значения являются
результатами одной машины, а не универсальным рейтингом.

Соберите эту опциональную цель после предоставления CMake-пакетов Boost.Process и libuv:

```bash
cmake -S . -B build-compare -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=OFF -DMWF_BUILD_EXAMPLES=OFF \
  -DMWF_BUILD_EXTERNAL_COMPARISON_BENCHMARKS=ON
cmake --build build-compare --config Release --parallel 2
./build-compare/MicroWorkflowFrameworkExternalBenchmark 50 7
```

## Интерпретация

Бенчмарк включает создание и завершение нативного процесса, которые формируют основную
часть стоимости. Он не сравнивает MWF с внутрипроцессным пулом потоков, поскольку эти
механизмы предоставляют разные границы отказов и ресурсов. CI выполняет короткую
smoke-нагрузку и загружает исходный CSV-подобный результат; публикуемые сравнения должны
использовать одинаковый исполняемый файл, хост, ограничения, число итераций, объём
выполненной работы, прогрев и порядок сценариев.

Бенчмарки являются подтверждением для разработки и никогда не устанавливаются вместе с
пакетом.
